# Архитектура: Blackbox Convoy

DE-петпроект на данных Argoverse 2 (траектории беспилотника и окружающих агентов).
Полный путь: сырой архив → medallion-слои → колоночная БД → аналитика.
Цель: production-подход к данным для ML (contract, quality gate, версионирование).

## Компоненты и их роли

- **Скрипты слоёв (src/bronze|silver|gold)** — medallion-трансформации; каждый слой
  читает выходы предыдущего строго через манифест, а не сканированием директории.
- **manifest.parquet (у каждого слоя)** — паспорт партии выходов: путь, размер, хеш,
  row_count, время. Даёт детерминизм входов, сверку целостности и lineage.
- **DVC (.dvc/, data/*.dvc, remote storage/)** — версионирование тяжёлых данных:
  в git только указатели с md5; копии в .dvc/cache; публикация через dvc push.
- **config/gold_schema_contract.json** — замороженный список столбцов и типов.
  Регенерируется только явно (generate_schema_contract.py) = изменение схемы
  всегда осознанное и закоммиченное.
- **Quality gate (в load_to_clickhouse.py)** — три уровня допусков: строка (≤1%
  выбросов → обнуление), файл (>1% → карантин), прогон (>0.1% карантина → красный, exit 1).
- **docker-compose.yml** — сервисы: ClickHouse, Qdrant. Код ETL живёт НЕ в контейнере,
  а в venv на хосте (упаковка ETL в образ — осознанно не сделано, см. «улучшить»).
- **.wslconfig** — ресурсы WSL2-машины (RAM/CPU), внутри которой живёт Docker на Windows.
- **.venv + requirements.txt (пины)** — воспроизводимость Python-окружения.
- - **Qdrant (docker-compose, порт 6337)** — векторная БД для similarity search.
  Хранит 40D эмбеддинги сценариев + payload (city, max_speed, n_tracks).
  Поиск по cosine similarity через HNSW-индекс.

## Три урока проекта

1. **Производные фичи — детектор дефектов.** Скорость 567 м/с вскрыла три механизма:
   fillna(0) создавал прыжки через пропуски; забытое деление на 0.1 (10 Гц) давало
   «метры за шаг» вместо м/с; diff() перепрыгивал границы треков на случайных
   совпадениях timestep. Фикс: NaN вместо нулей, DT=0.1, groupby(track_id).
2. **Тихая адаптация хуже громкого падения.** Ранний load молча выкидывал новые
   столбцы (reindex) — тихая порча данных. Контракт превратил дрейф схемы в инцидент
   с именем и текстом ошибки.
3. **Бинарный гейт не выживает на реальных данных.** Шум сенсора есть всегда;
   «любая аномалия = красный» означает перманентно красный. Работают допуски:
   строчная чистка шума, карантин для системных проблем, порог на весь прогон.
